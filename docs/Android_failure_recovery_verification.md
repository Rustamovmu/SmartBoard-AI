### Permission/error fix in the mobile repository

`NativeConnectedCapturePanel.tsx` previously interpreted `Error.message` as the stable error code, while Android's permission rejection carries a separate `code`. The new `connected-analysis-errors.ts` reads that field, preserves local storage/server errors and keeps unknown diagnostics generic. Camera unavailable/rejected/overloaded events now surface a useful connected-panel error. The fix changes no authentication policy, API/schema, calibration geometry, media encoding, file/catalog format or acknowledgment ordering. It does not establish a universal cause/fix for every reported sampling stall.

`connected-analysis-errors.test.ts` covers the real native message/code mismatch, plain native rejection objects, storage/server compatibility, unknown/inherited-key safety and error versus ordinary camera lifecycle states. Mobile TypeScript, lint, all **75 tests in 11 files**, production Vite build, Android/iOS asset sync, the Chromium fallback/privacy check and Android `testDebugUnitTest`, `assembleDebug`, `lintDebug` passed. Android reports **7 native unit tests**, **0 lint errors / 28 warnings**. iOS sync is not compilation or device evidence. No backend/Python application code changed, so their earlier suites were not rerun for this record.

Fixed normal APK: 21,880,510 bytes; SHA-256 `08a18b79b9311e44a66bcdc313aea5dd741be805ede4e5a6b480d0ba2854cc69`. All six production web files match the build. The normal APK contains no task certificate/probe; backup and cleartext remain disabled.

### Failed attempts and test instrumentation

Earlier Home observations missed the active-preview window, and a long-background return occurred after the stream ended. Fresh connections subsequently produced real worker candidates, which intentionally stop the preview for explicit review; a candidate expiring after 30 seconds is not a completed save. The user's report of a silent stall remains part of the investigation; the later native error presentation fix is described separately above.

An initial controller terminal truncated a long hook command; that hook did not arm and a watcher timed out without stopping the app. The terminal input limit was corrected. A first source-only interruption caught calibration rather than a three-image candidate; its complete one-file record correctly recovered. The repeated candidate-only interruption, not that earlier attempt, establishes the incomplete-bundle result. Initial automatic task-return probes failed in the temporary harness; these attempts and a user-return timeout are not counted as passing application checks. The final fixed-intent run produced the measured successful Home/return result above. A separate post-revocation currentDevice spot-check did not establish its expected rejection-code assertion; this record does not certify that subsequent GraphQL status/code. The real revocation mutation, streaming shutdown and offline file preservation are the verified boundaries.

Test hooks existed only in phone RAM and approved individual real candidates as explicit test-operator actions; they add no automatic candidate-saving feature. Temporary APK copies provided trust only for USB-forwarded `localhost`, with no phone-wide CA. The lifecycle probe and its fixed native actions existed only in that temporary copy, never in repository source or the normal APK. No image, video, calibration, measurement, catalog row, local path, capture hash value, credential, approval code or device serial was exported as evidence. The source-integrity check read bytes only inside the phone's existing bounded native/JS boundary and returned counts/booleans.

### iOS and production follow-up

The user confirmed **no iPhone/full-Xcode environment** and **no production deployment**. `xcode-select -p` returns Command Line Tools and `xcrun devicectl` is unavailable. The source's connected camera panel explicitly restricts sampling to Android; iOS live sampling remains unimplemented. No iPhone build/signing/install/device test was run, and no production HTTPS/WSS endpoint was available to validate.

Before the requested next stages can run, provide an iPhone/full-Xcode signing environment and the intended iOS capability, then a concrete production endpoint and access to its deployed configuration. The production audit must inspect the actual TLS chain/hostname and native WSS path, proxy buffering/temp storage, body/payload logging and tracing, worker cancellation/revocation, crash dumps/swap/snapshots and backup destinations/exclusions. Local TLS test trust and source-level no-archive behavior do not establish those deployment properties. No deployment was created or modified as part of verification.

Full production/F4 acceptance remains incomplete. Actual disk-full behavior, arbitrary power loss, broader permission/rotation/call/background interruptions, expiry during a pending commit, administrator blocking, iOS, classroom accuracy and deployment-wide retention still require separate evidence.
